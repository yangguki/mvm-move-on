# 스킨 관리 화면 + 기본 스킨 5종 (ADM-SKIN-01~09)

## Goal
관리자가 스킨을 목록으로 보고, 등록·수정·미리보기·활성/비활성·삭제(보호)할 수 있게 하고, 기본 스킨 5종을 제공한다.

## Context / decisions already made
- 기본 5종: 게임(네온 아케이드, `neon-arcade`, 이미 있음), 아이언 짐(`iron-gym`), 라이브 중계(`live-broadcast`), 파워 에너지(`power-energy`), WOD 칠판(`wod-chalkboard`).
- 모든 스킨은 같은 표준 레이아웃: 상단 정보 영역 + 하단 라운드 영상 박스(16:9, 1920×1080 기준). 성능상 영상을 둥글게 자르지 않고 라운드 프레임을 덮어씀. 스킨을 바꿔도 정보 위치는 그대로.
- 구현 방식(권장): 재생 엔진은 지금의 neon-arcade `player.js`(A/B 이중 버퍼, 카운트다운·휴식 음성, BGM, mvn:done)를 공통 엔진으로 쓰고, 스킨 차이는 테마 데이터(색 팔레트 주·보조·강조, 폰트, 배경 이미지/영상, 영상 박스 모서리 값, 정보 요소 표시 여부, 카운트다운·휴식·완료 화면 문구 스타일)로 표현. 스킨별로 엔진을 복사하지 않음.
- 스킨 옵션 예: pointColor, logoUrl, restImageUrl, startCountdownSec(기본 10), nextLeadSec.
- 정책 B: 게시 스냅샷에 스킨 테마 데이터(및 자산 URL)를 동결. 스킨을 고쳐도 재게시 전까지 기존 게시본은 그대로. 스킨 변경 시 해당 스킨을 쓰는 프로그램에 '재게시 필요'가 뜨게 기존 needsRepublish 계산에 포함.
- 자산 업로드는 기존 storage.service(R2/LocalStack) 재사용.
- 대상 브라우저 Tizen·webOS TV, ES2017.

## Next steps
1. DB: Skin 모델 정리(slug, name, theme 종류, description, thumbnailUrl, tokens JSON, isActive, isBuiltin). 마이그레이션 + seed에 5종 upsert.
2. API: `GET/POST/PATCH /skins`, `GET /skins/:id`, 자산 업로드, 활성/비활성, `DELETE`(사용 중이면 409 + 사용 프로그램 이름 목록, 기본 스킨은 삭제 불가). 목록에 사용 중 프로그램 수.
3. 공통 엔진: neon-arcade player.js를 테마 토큰을 받아 CSS 변수로 적용하게 바꾸고, 5종 토큰을 정의. 각 스킨이 확실히 달라 보이게(색·폰트·배경·영상 박스 모서리·상태 화면 문구 스타일). 외부 폰트는 TV에서 느릴 수 있으니 시스템 폰트 우선, 필요하면 로컬 woff2.
4. 게시: 스냅샷에 스킨 토큰 동결, 플레이어 API가 함께 반환, 플레이어가 그걸로 렌더. 기존 neon-arcade 게시본도 계속 재생돼야 함.
5. 관리자 `/skins`: 썸네일 카드 목록·검색(이름·테마), 등록/수정 폼(기본 정보, 색, 폰트, 배경, 모서리, 정보 요소 표시, 상태 화면 문구), 4개 상태(카운트다운·운동·휴식·완료) 미리보기를 1920×1080 비율로, 활성/비활성 토글, 삭제 보호 안내.
6. 빌더: 비활성 스킨은 새 선택 목록에서 숨김(이미 쓰는 프로그램은 유지).
7. e2e 스크립트에 스킨 1개로 게시→플레이어 상세에 스킨 토큰 포함 확인과 사용 중 삭제 409 확인 추가.
